# Alpha Radar V19.6｜簡單模型對照與事前決策驗證

## 先說用途
這是研究更新版，不是全面提高報酬的保證。這次20日開發重播較V19.5改善，5日退步，60日採用後結果不變。請勿因版本號增加而增加實際投入金額。

新版預設使用「簡單模型對照」。V19.5稀疏因子搜尋仍完整保留，可在側欄切換；兩者使用不同的選擇方法，舊報告不可冒充新設定下已訓練的結果。

## 安裝
1. 備份現有專案，解壓完整ZIP，將全部檔案放到GitHub專案根目錄。不是只換app.py，也不是把ZIP直接上傳當程式。
2. 保留data/、SQLite資料庫及Streamlit Secrets。不要將API金鑰放入GitHub。
3. Streamlit入口仍是app.py，依requirements.txt安裝套件。Python 3.11以上。
4. 確認畫面顯示V19.6。既有歷史行情可以使用，但模型與驗證設定改變時必須重新計算權重。

## 新的選股流程
- 先比較原模型與7個簡單價量對照：成交金額排序、成交金額搭配下檔韌性、成交金額搭配60日動能。
- 雙因子只比較25/75、50/50、75/25這三種權重。這是有限網格，不是窮舉所有最佳權重。
- 每個基準日，僅用當時以前已完成的最多8個不重疊持有區間，選出研究方案；至少需要4個區間。
- 再重播過去4個日期「當時事前選出的方案」來檢查是否可以採用。不能在同一段區間挑贏家後，把那段區間再稱為獨立驗證。
- 平均改善、拿掉單一區間、多數區間改善、0050、同股票池、成本、尾部風險與成交條件仍需檢查。未通過時沿用明確標示的原固定對照，研究候選另外顯示。

原模型不是V19.5每次自動調權後的結果，而是一直保留的固定原始模型。報告另提供V19.5採用後結果的逐案比較，不混用兩個基準。

## 基本面與籌碼
勾選選配資料後，額外提供成長與估值、投信與突破、法人與型態等3種研究組合。只有實際取得、時點符合規則的資料才能參加。缺值不補0或50分，也不默默把缺掉的權重分配給其他因子。

月營收、法人、融資、財報、現金流及估值的原下載／匯入流程保留；可用率、權限、公告／修訂時點仍須核對。本次重播包沒有基本面、籌碼原始資料，不能宣稱已驗證三面向的投資效果。成交金額不等於公司市值，價量買壓也不等於真正法人買超。

## 三個頁面
### 選股與規劃
選5／20／60個交易日，再選研究排名、通過採用檢查的排名，或原模型對照。每張卡片分開呈現日期、來源、分數、歷史結果與參考價區。權重是排序係數，不是資金配置比例。

### 歷史驗證
預設100個不重複基準日。新增「簡單對照組有沒有勝過複雜模型？」表，所有報酬以百分比呈現，缺資料顯示破折號。固定對照最好，不代表可以事後直接升格正式模型。

### 個股診斷
日線模型與當日行情分開。沒有取得核實即時價時，不把昨收或舊成交冒充可下單價格。盤中行情與手機瀏覽器尚未在本次正式環境驗證。

## 在電腦上重播
```bash
python -m pip install -r requirements.txt
streamlit run app.py
```
使用先前完整診斷包，不需重抓行情：
```bash
python run_v19.py --replay-bundle OLD_REPLAY.zip --as-of 2026-10-15 --dates 100 --seed 1920 --factor-design tournament_v196 --no-factor-audit --output results_v196 --data data/v19
```
這次交付的績效重播使用--no-factor-audit，重點是模型與交易政策比較；7組固定簡單對照仍全部計算。省略該參數可再產生既有逐因子診斷，但耗時增加。

保留V19.5搜尋作對照：
```bash
python run_v19.py --replay-bundle OLD_REPLAY.zip --as-of 2026-10-15 --dates 100 --seed 1920 --factor-design sparse_v195 --no-factor-audit --output results_sparse --data data/v19
```

## 重要界線
這100個日期已經反覆用於開發；換模型或隨機種子不會使它們成為新盲測。持有區間仍可能重疊。交易為次日開盤與到期收盤的假設，含既定成本與滑價，沒有真實下單、排隊或成交保證。

本次沒有將非線性模型、帶方向回歸、記憶型選股或新增停利停損規則放進正式核心，因為探索結果未見一致改善。V196_REPLAY_ANALYSIS.md保留成功與退步結果；V196_QA_STATUS.md列出本次真正完成的測試，不把工程測試次數當作獲利次數。
